## Mission

## Snapshot schema

Each exact product-cycle row MUST preserve:

- `observed_at_utc`
- `source_response_received_at_utc`
- `source_url`
- `source_sha256`
- `symbol`
- `contract_id`
- `product_state`
- `cycle_unit`
- `cycle_value`
- `up_pay_rate`
- `down_pay_rate`
- `up_break_even_probability`
- `down_break_even_probability`
- `invest_min_amount`
- `invest_max_amount`
- `index_price_scale`
- `pay_rate_scale`
- `settle_coin`

Optional fields are allowed only when actually observed from a proven source:

- trading window open/stop timestamps
- last trade date/time
- displayed/index price
- exact expiry timestamp
- settlement price
- result

Missing fields MUST remain null / absent. They must never be inferred.

Break-even probability is deterministic:
`p_BE = 1 / (1 + payout)`.

## Product scope

Capture every product returned by the exact detail source, regardless of ONLINE / PAUSE / OFFLINE state. State is data, not a reason to silently drop a row.

No product is promoted into a trading candidate by V0.12.

## Integrity

Every raw detail response MUST be hashed.
Every flattened row must be reproducible from the preserved raw JSON.
Rows from a single snapshot share the same source hash and observation id.

If the exact detail response is absent, non-JSON, unsuccessful, or does not contain a product list, the run MUST fail closed.
