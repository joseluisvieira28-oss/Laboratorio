# L2-RESILIENCY-001 — Corrected Source-Time & Stale-Payload Normalization Policy V0.2\n\nStatus: FROZEN PRE-OUTCOME / SOURCE-ONLY\n\n## Why V0.1 failed closed\nThe V0.1 schema audit incorrectly required raw.data.time to fall inside the S3 key hour and to be monotonic. Outcome-blind diagnostics proved that the hourly archive partition is governed by top-level envelope time, while raw.data.time can represent an older L2 payload delivered later.\n\nObserved over 50,717,748 records:\n- envelope outside key hour: 0\n- envelope backwards within objects: 0\n- payload after envelope: 0\n- payload backwards adjacent transitions: 64\n- payload duplicate timestamps: 158\n- all 2,768 prior outside-hour payload rows had envelope time inside the key hour.\n\nThis is an administrative source-time correction only. It does not alter the frozen L2 mechanism, asset, venue, depth levels or scientific horizons.\n\n## Canonical source clocks\n1. Top-level envelope time defines archive availability and hourly-object membership.\n2. raw.data.time is retained as payload/L2 snapshot time.\n3. A payload timestamp later than its envelope timestamp is invalid and fails closed.\n4. Envelope time must be non-decreasing across every contiguous PRESENT source segment.\n\n## Stale/late payload quarantine\nProcess each contiguous PRESENT source segment in envelope arrival order.\n- Maintain last_accepted_payload_time.\n- If raw.data.time < last_accepted_payload_time, classify the record STALE_LATE_PAYLOAD.\n- Preserve the raw record and its provenance, but do not allow it to replace the current book state or create a later scientific transition.\n- If raw.data.time >= last_accepted_payload_time, the record is eligible for normalized book-state continuity and last_accepted_payload_time is updated.\n- Equal payload timestamps are preserved in envelope order; they are not deleted merely because the millisecond timestamp is equal.\n- At every missing-hour boundary, reset book-state continuity. The first eligible record of the next PRESENT segment may establish a baseline but cannot form a transition across the missing gap.\n\n## Corrected schema gate\nSOURCE_SCHEMA_NORMALIZED_PASS requires all 8,707 raw objects and all decompressed records to satisfy:\n- exact frozen byte binding;\n- valid JSON/envelope/raw/data structure;\n- channel l2Book and coin BTC;\n- envelope timestamp inside the frozen S3 key hour;\n- envelope non-decreasing across each contiguous PRESENT segment;\n- raw.data.time integer and <= envelope time;\n- at least five levels per side;\n- positive prices, non-negative sizes and counts;\n- top-five bids strictly descending;\n- top-five asks strictly ascending;\n- best bid < best ask;\n- every stale/late payload deterministically identified by timestamp only and excluded only from normalized state continuity.\n\nSTALE_LATE_PAYLOAD records do not by themselves fail the corrected schema gate because their source semantics are now explicitly identified before outcomes. Any byte, JSON, channel/coin, envelope-time, future-payload, top-five or crossed-book violation still fails closed.\n\n## Firewalls\nNo sweep events, replenishment ratios, weak/strong labels, midpoint responses, returns, PnL, thresholds, 2025/2026 access, live trading or exchange mutation are authorized in this gate.\n\nDiscovery remains separately gated after SOURCE_SCHEMA_NORMALIZED_PASS.\n
