# Reproducible local Linux/Work runner plan — V0.7

Status: specification and pinned input inventory; not an implemented or executed deterministic replay runner.

1. Use a free, existing Linux amd64 host with local SSD, without validator keys. No spending authorization. Retrieve branch at its immutable closeout commit and verify every receipt with `python3 research/pos_unbonding_completion_001_v0_7_independent_replay/audit_receipts.py`. Verify genesis_pin.json SHA256 before InitChain. Top-level genesis validators are empty; initial set must be derived from the staking genutil genesis transactions by the exact v1 application, not treated as zero validators.
2. For each source_commit in historical_version_inventory.json: `git clone https://github.com/CoreumFoundation/coreum.git coreum-src`; `git -C coreum-src checkout --detach SOURCE_COMMIT`. Use that revision's go.mod and official build instructions/toolchain. Archive source tree hash, Go version, CGO settings, wasmvm shared libraries, build logs, binary version and SHA256. Alternatively download official cored-linux-amd64 assets listed in inventory, verify official checksums where provided and independently hash bytes. Do not run latest binary against genesis. Exact activation schedule remains unverified; v2.0.0/v2.0.1 release advisories explicitly recommend v2.0.2, which cannot be retroactively assumed equivalent at all heights.
3. Complete the upgrade ledger: plan name, submit/enact transaction, execution height, predecessor binary, successor binary, store migrations and local replay observation. AppliedPlan source queries are hints, not independent proof. Decode canonical governance transactions from raw blocks; confirm in locally executed state. Halt before any unknown upgrade. Patch plans matter as well as major versions.
4. Implement and audit version-specific Go transport/importer using the exact Tendermint/CometBFT types pinned by go.mod. Import block JSON into typed block, recompute Hash/DataHash, marshal canonical vote sign bytes, verify commits against full paginated evolving validator sets. Compare header ValidatorsHash and NextValidatorsHash; prove genesis initial validator linkage. Handle absent votes, nil block IDs, part-set headers and consensus-version transitions explicitly. The Python acquisition script is NOT this importer.
5. Construct offline application executor for each ABI generation: InitChain(genesis), exact ABCI block request sequence with consensus evidence/last commit, Commit, persist application DB and ABCI responses. Ensure execution engine reproduces consensus state/validator updates and upgrade handoff. Do not use `cored start` as a substitute: normal P2P sync could change transport provenance and may discard responses, sign or broadcast. No private validator, P2P, public listener or wallet is needed for offline execution.
6. Fetch raw blocks in contiguous 10,000-height chunks beginning at 1, plus successor headers. Fixed Source A https://archive.rpc.mainnet-1.tx.org only. Record raw response SHA256, size and UTC, JSON-RPC error and retry history. Bounded retry never skips a missing height. No block_results. Run a 1,000-block pilot after executor/toolchains/upgrade ledger are implemented to measure download size, CPU, wall time and disk. Extrapolate from actual results; report uncertainty. No current pilot estimate or claim of Actions infeasibility exists.
7. Resume chunks only from own previous verified checkpoint: full prefix receipt hash, state DB/files hashes, application version/binary/dependencies, blockstore hash, local results hash, last height, expected next height and AppHash. Verify predecessor manifest and hash bytes before resuming. Always retain genesis prefix evidence. Never inject a public snapshot.
8. At 5M/10M/15M reproduce local canonical header hash/time and correct AppHash offset against frozen anchors. Local post-H Commit compares header H+1. Continue contiguous replay through the end of the frozen completion interval: 15M is only January 2024, so it cannot establish whole-2024 census coverage.
9. Adjudicate G2 computation independently of transport, then five-chain source coverage, then completion extraction/lifecycle reconciliation. The global SOURCE_GATE_PASS cannot follow from a Coreum-only match.

Missing implementation deliverables: typed block importer/crypto verifier, offline executor, complete authenticated upgrade ledger, pinned executable binaries/dependencies, pilot/resource receipt and contiguous replay checkpoint receipts. Until they exist, fail closed. A receipt-audit Actions workflow may verify saved bytes only; it must never label that job replay success. Do not dispatch billable or free-quota-consuming work without confirming zero spending; this task performs no Actions dispatch.
