# CRYPTO LAB AGENT OS V0.1

Purpose: reduce context reconstruction, authority drift, accidental hindsight and wrong-branch decisions without changing any scientific rule, candidate, threshold or execution permission.

## What this layer does
- provides a universal agent entrypoint;
- records canonical policy anchors by branch + commit;
- defines deterministic authority-resolution behavior;
- separates scientific, lifecycle, promotion, execution and runtime truth;
- forces fail-closed behavior on unresolved conflicts.

## What this layer does NOT do
- merge research branches;
- promote or demote candidates;
- open protected outcomes;
- change frozen costs, thresholds, signals or horizons;
- authorize orders, exchange mutation, wallets or capital;
- declare a branch canonical merely because it is newer.

## Core model: five independent authority planes
1. EXPERIMENT SCIENCE — exact protocol, freeze, receipt, closeout.
2. LIFECYCLE GOVERNANCE — whether exact work may continue, sleep, die or be superseded.
3. PROMOTION — Tier evidence and promotion requirements.
4. EXECUTION / OPERATOR — whether/how a scientifically eligible candidate may be transported.
5. RUNTIME TRUTH — what is actually deployed, armed, healthy, stale, blocked or reconciled.

Never collapse these planes into one status.

## Authority conflict algorithm
A. Match exact identity first.
B. Prefer explicit supersession over date/name inference.
C. For exact science, frozen protocol + canonical receipt + terminal closeout outrank global indexes.
D. A later global policy is prospective unless it explicitly re-adjudicates under preserved historical evidence.
E. Execution authorities cannot rewrite science.
F. Runtime observations cannot rewrite frozen scientific verdicts.
G. If two same-plane authorities conflict and neither explicitly supersedes the other: FAIL_CLOSED.

## First implementation scope
V0.1 is intentionally small. It establishes governance rails before automation. Future versions may add a generated branch census, machine-readable candidate lineage graph and CI validation, but only after this control plane is reviewed.
